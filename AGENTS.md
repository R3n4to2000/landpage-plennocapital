# AGENTS.md

## Projeto

Este repositório contém a landing page institucional da **Plenno Capital**.

A página deve ser construída com **Vite + React** e seguir rigorosamente a identidade visual, o posicionamento e o tom de voz definidos pela marca.

O objetivo é criar uma experiência digital premium, sofisticada, minimalista e institucional para uma empresa de estratégia patrimonial e consórcios.

---

## Stack esperada

- Vite
- React
- JavaScript
- CSS moderno
- HTML semântico

Evite adicionar dependências desnecessárias.

Se uma biblioteca externa for realmente útil, priorize soluções leves e amplamente utilizadas.

Não adicionar backend, banco de dados, autenticação ou integrações externas sem solicitação explícita.

---

## Referências obrigatórias

Antes de implementar qualquer alteração visual, considere como fonte principal:

1. O **Manual de Marca da Plenno Capital** fornecido no projeto.
2. O **print de referência da primeira seção / hero** fornecido junto ao prompt.

A primeira seção da landing page deve permanecer visualmente muito próxima do print de referência.

As demais seções devem evoluir a partir da mesma linguagem visual.

Não reinterpretar a marca de forma genérica.

---

## Identidade visual

### Cores

Use estas cores como tokens principais:

```css
--plenno-blue: #020711;
--plenno-gold: #D4B474;
--plenno-ivory: #F5F2EA;
--plenno-white: #FFFFFF;
```

Regras:

- O **Azul Plenno** é o fundo/base predominante da interface.
- O **Dourado Plenno** deve ser usado com precisão e moderação.
- Branco e marfim são cores de apoio para textos, contraste e respiro.
- Não utilizar fundos claros como base dominante da landing page.
- Não exagerar em gradientes, brilhos, sombras, glow ou efeitos metálicos.

O dourado deve aparecer principalmente em:

- detalhes;
- linhas finas;
- ícones;
- pequenos destaques;
- números;
- títulos curtos;
- CTAs;
- bordas ou marcadores pontuais.

---

## Tipografia

A referência principal da marca é **DejaVu Sans**.

Direção:

- títulos com presença forte;
- títulos importantes podem utilizar caixa alta e tracking amplo;
- textos corridos devem ser limpos, legíveis e objetivos;
- manter hierarquia visual clara;
- evitar fontes excessivamente decorativas.

Caso DejaVu Sans não esteja disponível como asset local, utilizar uma alternativa sans-serif neutra somente até que a fonte oficial seja adicionada.

A composição deve priorizar:

- bastante respiro;
- poucos elementos por bloco;

## Responsividade

A página deve funcionar bem em:

- desktop;
- notebook;
- tablet;
- mobile.

Priorize desktop na primeira implementação, pois o print de referência é desktop.

Depois adapte sem destruir a hierarquia visual.

Em mobile:

- transformar menu em navegação compacta;
- empilhar conteúdos quando necessário;
- preservar respiro;
- evitar redução excessiva de tipografia;
- manter CTAs confortáveis para toque;
- não permitir overflow horizontal.

---

## CSS e layout

Preferir:

- CSS Grid;
- Flexbox;
- `clamp()` para escalas responsivas;
- custom properties;
- containers com largura máxima;
- espaçamentos consistentes;
- breakpoints simples.

Evitar:

- excesso de valores absolutos;
- posicionamento fixo desnecessário;
- hacks de layout;
- duplicação de estilos;
- CSS inline em excesso.

Criar tokens para:

- cores;
- espaçamento;
- radius;
- largura de container;
- tipografia;
- transições.

---

## Interações

Interações devem ser discretas e premium.

Permitido:

- fade suave;
- hover sutil;
- mudança discreta de borda;
- deslocamento mínimo;
- underline animado;
- accordion suave.

Evitar:

- animações chamativas;
- parallax excessivo;
- zoom agressivo;
- partículas;
- efeitos neon;
- animações contínuas sem função.

Respeitar `prefers-reduced-motion`.

---

## Assets

Não recriar a logo manualmente se os arquivos oficiais estiverem disponíveis.

Prioridade:

1. utilizar os assets oficiais fornecidos;
2. preservar proporções;
3. preservar área de respiro;
4. não aplicar efeitos;
5. não alterar cores.

Caso um asset necessário ainda não exista no projeto, deixar o código preparado para substituição posterior e indicar claramente o arquivo esperado.

Exemplo:

```text
src/assets/brand/plenno-logo.svg
src/assets/brand/plenno-monogram.svg
src/assets/images/hero.jpg
```

- não alterar arquivos não relacionados ao pedido;
- preservar a estrutura existente quando ela já estiver organizada.

## Antes de finalizar qualquer tarefa

Verificar:

1. A aplicação inicia com `npm run dev`.
2. Não há erros no console.
3. Não há overflow horizontal.
4. O layout está responsivo.
5. A hero continua fiel ao print de referência.
6. A paleta está coerente com a marca.
7. O dourado não está sendo usado em excesso.
8. A página não parece uma fintech genérica.
9. Não existem promessas financeiras indevidas.
10. A navegação por teclado continua funcional.
11. Textos e métricas continuam fáceis de editar.
12. Não foram adicionadas dependências desnecessárias.

---

## Regra de decisão

Quando houver dúvida entre:

- adicionar mais elementos;
- ou preservar simplicidade e respiro;

prefira **simplicidade e respiro**.

Quando houver dúvida entre:

- um efeito visual chamativo;
- ou uma solução discreta;

prefira **a solução discreta**.

Quando houver dúvida entre:

- linguagem comercial agressiva;
- ou linguagem estratégica e clara;

prefira **a linguagem estratégica e clara**.

A landing page deve parecer uma extensão natural da identidade institucional da Plenno Capital.
